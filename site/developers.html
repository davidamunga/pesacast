Developers

Build on the webhook.

The phone posts each payment to an HTTPS address you control. Signed, retried, and the same format every time.

Read this first. A payment SMS is not proof of payment. It can be faked or delayed. Treat these requests as notifications, and confirm money-moving events through Safaricom’s Daraja callbacks.

The request

POST https://your.server/pesacast
Content-Type: application/json
Idempotency-Key: ABC123XYZ@2026-10-24T10:00:00+03:00
X-PesaCast-Device-Id: 5b0f6c1e-6a9a-4f4f-9e0e-2c5d7c0a9d11
X-PesaCast-Timestamp: 1761292801
X-PesaCast-Signature: v1=<hex>      (only if you set a signing secret)
Authorization: Bearer <token>       (only if you set a token)
{
  "schema_version": 1,
  "source": "android",
  "device_id": "5b0f6c1e-6a9a-4f4f-9e0e-2c5d7c0a9d11",
  "exported_at": "2026-10-24T10:00:01.234Z",
  "count": 1,
  "transactions": [{
    "type": "mpesa_txn",
    "direction": "received",
    "amount": 500.0,
    "currency": "KES",
    "from": "JANE DOE",
    "ref": "ABC123XYZ",
    "time": "2026-10-24T10:00:00+03:00",
    "balance": 1500.0
  }]
}

The desktop app can post the same envelope, with "source": "desktop". Ignore fields you do not know; new optional fields can appear without changing schema_version.

What your server should do

  1. Check the signature. v1= plus the hex HMAC-SHA256 of the text <timestamp>. followed by the raw body, keyed with your secret. Compare in constant time. Reject timestamps more than a few minutes old.
  2. Ignore test pings. The “Save and test” button sends "test": true with no transactions. Answer 2xx and record nothing.
  3. De-duplicate. Delivery is at-least-once. Use Idempotency-Key, or a unique constraint on ref plus time. The phone and the desktop use the same key.
  4. Answer quickly. Store, reply, process later.

What the phone does with your answer

You answerThe phone
2xxDone. Removes it from its queue.
408, 429, 5xx, or no answerRetries with backoff (5 seconds, doubling, up to 15 minutes), same key.
401, 403Pauses and keeps the queue until the settings change. Nothing is lost.
Redirects, other 4xxDrops that transaction and shows the error. Do not use 4xx for something you could process later.

The queue holds up to 500 transactions for up to seven days. Requests must be HTTPS, redirects are not followed, and there is a ten-second timeout.

Verify a signature (Node)

import crypto from "node:crypto";

function verify(secret, timestamp, rawBody, header) {
  const expected = "v1=" + crypto.createHmac("sha256", secret)
    .update(`${timestamp}.`).update(rawBody).digest("hex");
  return header.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(header), Buffer.from(expected)) &&
    Math.abs(Date.now() / 1000 - Number(timestamp)) < 300;
}
